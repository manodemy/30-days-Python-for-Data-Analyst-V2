# Manodemy — Homepage Redesign + Refresh-Bug Fix

## Part A — Fix the "refresh → Day 01" bug (all tracks)

**Root cause:** `public/Version-3/scrimba-engine.js:3823-3828` detects the day from `window.location.pathname` using a legacy regex that only matches `/dayXX.html`:
```js
const pathMatch = window.location.pathname.match(/day(\d+)\.html/i);
```
Modern served routes are `/notebook/sql-day05` (Vercel rewrites internally to `/sql/day05.html`, but the browser's `location.pathname` stays `/notebook/sql-day05`). The regex fails → `defaultDay` falls back to `'day01'` → **every refresh jumps to Day 01.**

**The fix (already proven in this codebase):** `public/notebook.js:178-185` already has the correct, robust `getDayId()` that matches `sql-day` / `excel-day` / `day` from the pathname. I'll port that exact logic into `scrimba-engine.js`, making it the single source of truth.

**Files changed:**
1. `public/Version-3/scrimba-engine.js` (~line 3823) — replace the broken `pathMatch` block so `defaultDay` derives from `/sql-dayXX` (and any `dayXX`/`dayXX.html`/query fallback). Also harden the day-change URL sync (~line 3884) so it works for both `/notebook/sql-dayXX` and legacy `/sql/dayXX.html`.
2. **Excel** (`public/excel/*.html`): each day is its own static HTML file — **not affected by the bug**; no change needed.
3. **Python** (`public/python/python-engine.js:88-98`): reads `?day=N` from query string and refresh preserves it — **not affected by the bug**. I'll leave it as-is (it's the only one of the three that uses query params, and it already works).

Result: refreshing any SQL day page (and navigating via the in-page dropdown) stays on the correct day.
